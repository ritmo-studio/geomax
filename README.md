# geomax

Сайт ГЕОМАКСа на `ritmo-engine`: страница — PHP-файл с инклюдами, HTML
отдаёт сервер, сборка нужна только для CSS и JS. Базы данных нет.

Блоки страницы приехали **снимком** из библиотеки `seo-design-system`
(копия под клиента `geomax v.0.34 SEO DS`, Figma `NY7nGOBlQt9Zbos7riZKWf`)
и сохранили префикс `sds-`. Связи с библиотекой нет: правки отсюда туда
сами не едут, обновления системы сюда не приходят. Версии — `blocks.json`.

## Как устроено

| Где | Что |
|---|---|
| `public/` | Докрут. Страница `index.php`, `404.php`, собранные `assets`, `robots.txt`, `sitemap.xml`, `site.webmanifest` |
| `engine/` | Копия `ritmo-engine` 0.15: `<head>`, подвал документа, 404, сборка, карта сайта |
| `tokens.css` | Токены библиотеки + правки проекта + мост на имена `--rs-*` движка |
| `atoms/`, `blocks/` | Снимок библиотеки, разложенный по файлам: один атом или блок — одна папка |
| `content/` | Тексты и данные блоков, по файлу на блок |
| `snapshot/` | Исходный снимок как его отдала библиотека: фрагменты `.html`, монолитный `sds.css`, самодостаточный `preview.html` |

Порядок склейки задаёт `engine/tools/build.py`: токены → база движка →
атомы → блоки движка → блоки сайта, внутри каждой группы по алфавиту.
Отсюда два имени, которые выглядят странно и такие нарочно:
`atoms/_base` (база библиотеки обязана идти до атомов) и
`blocks/zz-overrides` (правки проекта обязаны идти последними).

### Сборка

```
python3 engine/tools/build.py          # css + js в public/assets, sitemap.xml
php engine/tools/render.php index.php  # рендер страницы в консоль
```

`build.py` ловит незаполненные плейсхолдеры и вывод до заголовков в PHP.
Собранные `public/assets/css/main.css` и `main.js` коммитятся: деплой —
`git pull` в папку сайта, сборку там никто не запускает.

## Что пришло из снимка и что изменено при переносе

Разметка блоков совпадает со снимком — это проверяется рендером: вывод
`render.php` отличается от `snapshot/*.html` только тем, что перечислено
ниже. Всё остальное побайтово то же.

- `sds-anim` → `rs-anim`, `.sds-js` → `.rs-js`, `.sds-in` → `.is-in`.
  Наблюдатель появления на движке один, свой (`engine/base.js`), поэтому
  библиотечный выброшен вместе с его правилами показа. Два наблюдателя на
  одних элементах — то, ради чего это правило и написано.
- Из `sds.js` выброшены вендорный Lenis и его запуск: плавную прокрутку
  включает движок (`engine/base.js` + `public/assets/js/vendor/lenis.min.js`).
- Логотип и знак студии вынуты из `data:`-URI в файлы `/assets/img/*.svg`.
  Иконки и арт плиток остались инлайном в CSS: двадцать одна маска по
  300–800 байт — это 21 сэкономленный запрос, а не экономия на весе.
- Блоки, которых нет на этой странице (`faq`, `price-list`, `doctors`
  и ещё восемь), в сайт не поехали вовсе: снимок отдаёт весь CSS
  библиотеки, странице нужна треть.
- `id` секций (`#advantages`, `#objects`, `#rent`, `#services`,
  `#contacts`, `#lead-form`) проставляет `public/index.php` параметром.
  У блока своего `id` нет: он не знает, сколько раз его поставят.
  `icon-cards` на странице дважды — отсюда это правило и видно.
- Отклонения копии движка от `ritmo-engine`: нет `blocks/preloader`,
  из `base.css` убраны `@font-face` студии «Ритм», в `page-404` свой
  логотип и кнопка (атома `rs-link` на этом сайте нет), в `head.php`
  сайтовые `prodHost`, `og:site_name`, `theme-color` и пустой
  `$preloadFonts`. Всё это `engine.json` относит к сайтовому.

`snapshot/` не правим и в сборку не включаем: это то, что утвердил
заказчик, и при расхождении права она, а не библиотека, ушедшая вперёд.

## Медиа

Растр и видео в репозитории не живут (`.gitignore`): они лежат на хостинге
в `public/assets/img` и `public/assets/video`, в коде стоят пути от корня —
`/assets/img/...`. Вектор (логотип, иконки, арт) — часть кода и коммитится.

Сейчас фотографии и видео — **заглушки** (серый прямоугольник инлайном,
как в утверждённом снимке), постер первого экрана ссылается на
`/assets/img/hero-poster.jpg`, которого ещё нет. Это этап 8: мастера
придут от дизайнера, нарезка — `tools/make-images.py` в библиотеке,
меняются только пути в `content/`, вёрстка не трогается.

## Перед запуском

1. **Домен.** Везде стоит `geomax-spb.ru` — это адрес сайта компании,
   куда ведёт ссылка из подвала. Настоящий адрес этой страницы ещё не
   назван. Подставить в `engine/blocks/main/head.php` (`$prodHost`),
   `public/index.php` (`$pageUrl`), `public/404.php`, `public/robots.txt`,
   `content/schema.php`. От `$prodHost` зависит автоматический `noindex`
   на небоевых хостах: ошибка здесь либо закроет боевой сайт от поиска,
   либо откроет стейджинг.
2. **Обработчик формы.** `content/lead-form.php` отдаёт `form_action: '#'`:
   на движке обработчика пока нет вообще (`engine.json`, раздел `open`).
   Вместе с ним — CSRF-токен, ограничение частоты по IP и проверка длины.
3. **Шрифт.** Manrope приходит ссылкой на Google Fonts из `$headExtra`.
   Положить woff2 на хостинг, добавить `@font-face` и `$preloadFonts`.
4. **Фавиконки.** `head.php` ссылается на `/assets/img/icons/favicon.svg`
   и `apple-touch-icon.png` — их ещё нет, нужны от дизайнера. Там же
   картинка шеринга `/assets/img/share.jpg`.
5. **Счётчик.** `$metrikaId = 0` в `engine/blocks/main/footer.php` — тега
   нет вообще. Появится номер — вписать, на боевом он включится сам.
6. **nginx** по `engine/tools/nginx.conf.example`: докрут с `/public`
   на конце, маршрут 404, канонический адрес, заголовки кэша. Проверить
   ACME-челлендж до переключения докрута.
7. После переключения: `curl -sI https://САЙТ/ | grep -i x-robots-tag` —
   на боевом пусто, на стейджинге `noindex`.
